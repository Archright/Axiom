## 1. 질의 (Query)

워크플로별 구성비가 창 평균을 지배한다는 관측(closure 문서 §6 구성 분석 인용,
§2.2)은 RESID-22 ③ 사전등록 평가 계약(§2.4)의 **설계 결함**인가?

핵심 질의:

- **(a)** 기존 **FAIL 판정을 유지**할 것인가 — 계약은 전체 런 모집단의 wall-time
  분포 비교를 정의했고 그 정의대로 판정됐다는 해석.
- **(b)** 또는 **워크플로 정규화를 포함한 창 재설계의 신규 사전등록 계약을 만들
  것인가** — 계약이 측정하려던 대상(개선의 존재)과 계약이 정의한 판정식(혼합
  모집단 창 평균 비교) 사이의 정렬 결함이라는 해석.

본 문서는 (a)/(b) 중 어느 쪽도 권고하지 않는다(§4, §5).

### 2.1 판정 원문 (closure 문서 §6 인용)

| 기준 | 요구 | 실측 | 결과 |
|---|---|---|---|
| 창B 표본 | ≥5 | n=158 (Ubicloud 실측) | 충족 |

- "**판정: FAIL — ③ 사전등록 관측 기준 미충족.** 계약의 3조건 중 표본 요건만 충족"
  (closure §6).
- 민감도(closure §6 인용): 창A를 같은 엔트리 전체 8건(n=8: mean 209.5, p95 652.8)
  또는 창A 전체 80건(n=80: mean 221.7, p95 974.1)으로 바꿔도 mean 기준은 +18.2s /

- ledger 상태 결정(closure §7 인용): 상태 계약(3분기) 적용 조항 "readback 확인 +

  **RESID-22 = OBSERVING / DEFERRED 유지**.

### 2.2 구성 분석 (closure 문서 §6 "구성 분석(해석 보조 — 계약 판정 아님)" 인용)

- 워크플로별 평균(창A 전체 80 vs 창B 158): `admission-gate` 959.4→780.0
  (**−179.4s**, 최대 개선원), `generation-acceptance` 74.9→56.8(−18.1s), **나머지
  6개 워크플로는 ±5s 이내**.
- "즉 nimcache 분리의 개선은 admission-gate 단일 워크플로에 집중되며, 8종 혼합
  모집단의 창 평균은 엔트리 구성비에 지배된다(창A 최근 5건은 8종 중 5종만 포함)."
- "단일 워크플로 개선(−179.4s ≥ 120s, p95 1093.1→923.0)은 계약이 정의한 모집단
  (전체 런)과 다른 열람이므로 **계약 충족으로 기록하지 않는다** — 다음 관측 설계
  (창 재설계) 시 검토 대상이다."

### 2.3 데이터 비대칭 — 창A 5런 vs 창B 158런

- 창A는 **5런만 원시 기록**(closure §5-1 전수 표; T 직전 최근 5런, 모두 Ubicloud
  실측)이다. 창A의 모집단은 80런이지만(closure §3), 그 전체의 워크플로별 재판정에
  필요한 표본 확장은 **신규 API 수집**(모집단 열거 + 런별 jobs 공급자 실측)을
  요한다 — closure 문서는 그 수집을 수행하지 않았다.
- 창B는 **158런 원시 전수 기록**(closure §5-2)이다. §2.2의 창A 측 워크플로별 평균
  (80런)은 closure 문서가 이미 수집·기록한 값이지만, 창A **최근 5건** 표본의
  워크플로별 분해는 기록돼 있지 않다.
- 계약이 정의한 모집단(closure §2 사전등록 원문 인용): "주 비교는 동일 공급자
  (Ubicloud) 창으로 한정: 창A = T 직전의 최근 ≥5건(Ubicloud), 창B = [T, T2) 구간
  런(Ubicloud)" — **워크플로별 층화(층 내 비교)는 계약 어디에도 정의돼 있지 않다**
  (부재 사실).

## 3. 해석별 파생 요구 (Derived requirements)

### 해석 A — 설계 결함 아님

**의미**: 계약은 전체 런 모집단(동일 공급자 창)의 wall-time 분포 비교를 정의했고,
판정은 그 정의대로 이행됐다. 혼합 모집단의 창 평균이 엔트리 구성비에 지배되는 것은
평균의 산술적 성질이지 측정 오류도 계약 위반도 아니다. FAIL은 "계약이 요구한 개선
크기(전체 모집단 mean ≥120s)가 실현되지 않았다"는 올바른 판정이다.

**파생 요구**:

- 기존 FAIL 판정 유지 — 추가 측정·계약 변경·창 재설계 없음.
- ledger OBSERVING/DEFERRED 유지(현행). 다음 트리거는 closure §7이 이미 기록한
  "공급자 단일화된 창(전환 안정화 후)의 재관측" — 계약 개정 없이 동일 계약으로
  재관측 가능한 상태다.
- 이 해석 아래에서도 남는 것: nimcache 분리의 단일 워크플로 개선(−179.4s)은 계약
  어휘로는 기록될 수 없다 — "개선 없음"과 "전체 모집단 기준 미달"은 다른 진술이며,
  정본이 기록하는 것은 후자뿐이다(closure §6이 이미 이 지위를 기록).

### 해석 B — 설계 결함 (계약이 답할 질문을 잘못 정의)

**의미**: 8종 워크플로 혼합 모집단의 창 평균은 엔트리 구성비에 지배되므로(§2.2
인용), 창A 5런 vs 창B 158런의 구성비 차이가 개선을 희석·왜곡할 수 있다 — 즉 계약이
측정하려던 대상(개선의 존재)과 계약이 정의한 판정식(혼합 창 평균 비교) 사이에
정렬 결함이 있다.

**파생 요구**:

1. **신규 사전등록 계약 필요** — 워크플로 정규화 기준(예: 워크플로별 층화 mean/p95
   비교 또는 구성비 고정 가중) + 창·표본 요건의 재정의. 구체 판정식은 신계약의
   사전등록 본문이 정의한다 — 본 ADR은 정의하지 않는다.
2. **창A 신규 API 수집은 인간이 계약 개정을 승인한 후에만** 수행한다. 승인 전
   수집은 사후 설계가 판정을 선취하는 행위다(§0.9 사후 기준 변경의 대상).
3. **결과 소급 적용 금지** — 신계약의 판정식을 기존 FAIL 판정에 소급 적용해 FAIL을
   뒤집는 것은 금지된다. 12월 계약 §2.4(PR #1182 착지)의 명문화 원리: "기준 개정은
   12월 결과와 무관한 사전 개정(별도 PR + 개정 사유 기록)으로만 가능하며, 결과
   관측 이후의 개정은 그 결과의 판정에 소급 적용될 수 없다".
4. 기존 FAIL 판정의 지위: FAIL은 FAIL로 기록 유지 — 신계약은 미래 관측의 계약이지
   과거 판정의 재판정이 아니다.

## 4. 결정 옵션 (Options)

**권고 없음 — 인간(계약 소유자) 판정 대기.** 아래 옵션들은 이 문서가 제시하는
선택지며, 조합·변형 선택도 인간 권한이다.

### 옵션 A — 기존 FAIL 판정 유지 (변경 없음 — 디폴트)

해석 A 채택. 계약·판정·ledger 상태 모두 현행 유지, 추가 작업 없음.

- **의미**: 창 재설계는 이루어지지 않고, RESID-22의 다음 관측도 기존 계약 어휘
  (공급자 단일화된 창의 재관측)로 수행된다.
- **비용/남는 것**: nimcache 단일 워크플로 개선(−179.4s)은 계약 어휘로 영구 기록
  불가 — RESID-22는 "전체 모집단 기준 미달"로만 역사에 남는다. 구성비 지배 문제는
  closure §6이 기록한 현행 지위("다음 관측 설계 시 검토 대상")에 머문다.
- **디폴트 근거**: 결정이 없는 한 현행 판정이 유지된다 — 본 옵션은 "아무 것도
  하지 않는다"의 정본화다.

### 옵션 B — 신규 사전등록 계약 (해석 B 채택 — 결정 후 별도 워크스트림으로만)

해석 B 채택. 워크플로 정규화를 포함한 창 재설계 계약을 **신규 사전등록**하고, 그
승인 후 창A 신규 API 수집과 재관측을 **별도 워크스트림**에서 수행한다.

- **경계**: 본 ADR의 착지와 옵션 B 선택은 계약 개정이 아니다 — "새 계약을 만들
  권한"의 부여일 뿐이며, 계약 본문·판정식·표본 정의는 후속 별도 PR에서
  사전등록된다. 기존 FAIL 판정은 소급 재판정되지 않는다(§3-B.3). 창A 신규 API
  수집은 신계약 승인 **후에만** 시작된다(§3-B.2).
- **비용**: 창A 전수 공급자 실측의 API 수집 비용(closure §3 방법론 준용 시 모집단
  열거 + 런별 jobs 조회), 신계약 문서·검증 비용, 그리고 관측 설계 자체를 다시
  사전등록하는 절차 비용.
