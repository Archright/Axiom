# ADR-0012: Atomic VKD Sync (`ax vkd sync`)

## Status
Accepted (2026-08-07, human architect)

## Context
The VKD lifecycle previously required a **manual 3-step SOP**:
1. `ax prove --limit 25 --update-lock` (regenerate certificates + commit the canonical lock)
2. Safe orphan cleanup (remove stale certificates not present in the manifest)
3. `ax baseline update` (refresh the monotonic baseline SSOT)

Each step is a distinct binary/CLI invocation, so a partially-executed manual run could
leave orphaned certificates, a stale baseline, or an inconsistent lock. This is a failure
mode the integrity engine should make impossible.

Separately, the integrity lock (`data/universe_merkle.lock`) was being conflated with a
bounded-prove progress checkpoint written by `proof_universe_lock_gate`. Normal
`ax prove` runs were implicitly expected to persist the lock even when the operator never
asked for it.

## Decision
Introduce a single atomic composite command **`ax vkd sync`** that runs, in order:

1. **Prove** — invoke the same entry used by `ax prove` (`runAxiomEngineCli`) with
   `--limit 25` and `updateLock=true`, regenerating certificates and committing the
   canonical lock.
2. **Non-destructive orphan check** — read the vault manifest (generated by the prove
   run) to count the referenced certificates and REPORT any orphans, without deleting
   them. Destructive removal is deliberately excluded: the per-run manifest only covers
   the current batch, so deleting by that set would destroy committed certificates
   (integrity hazard). Destructive orphan cleanup remains available only via the
   `writeCertificates` full-rebuild path, which derives the expected set from the
   complete function list.
3. **Baseline update** — delegate to `cmdBaselineUpdate()`, preserving the monotonic VKD
   ratchet (ADR-0011).

### Lock-Write Authority (canonical runs only)
`data/universe_merkle.lock` is **Git-ignored / untracked**. Its in-memory value is always
computed and validated on every run, but it is **persisted to disk only by canonical runs**:
`ax vkd sync` or `ax prove --update-lock` (`updateLock=true`). Normal `ax prove` / any
`--limit` run keeps the lock in-memory. All other integrity side effects (global symbol
graph snapshot, Merkle hash, reasoning-trail/provenance-log drain, audit buffer flush)
remain unconditional on every run. The gate's bounded-prove progress checkpoint was moved
to a separate path `data/universe_merkle_gate_checkpoint.json` so it never clobbers the
canonical lock.

## Consequences
- The manual SOP is replaced by a single atomic command.
- Non-canonical runs never write the lock to disk, preventing accidental churn/laundering.
- Orphan cleanup is whitelisted by the exact certified `irHash` set, so only unmanifested
  stale certificates are removed.
- Baseline updates still respect the monotonic ratchet.
- Decision cards `DECISION-0013` (lock persistence gating) and `DECISION-0014` (canonical
  lock authority) bind the lock-write changes in `proof_universe_commit.nim`.
