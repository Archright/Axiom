# SearchWeb 불능 원인 조사 기록

- **조사일**: 2026-05-31
- **조사 도구**: Context7 MCP (`/moonshotai/kimi-cli`, `/websites/moonshotai_github_io_kimi-cli_en`), Shell, curl

---

## 1. 현상

`SearchWeb` 도구 호출 시 `403` 에러 반환.

## 2. 근본 원인

**Kimi Code 계정의 웹 검색 API(quota) 소진**

```
curl -H "Authorization: Bearer <token>" https://api.kimi.com/coding/v1/search
→ 403 {"error":{"type":"access_terminated_error",
     "message":"You've reached your usage limit for this billing cycle."}}
```

## 3. 아키텍처 — 두 파이프라인의 독립성

SearchWeb과 MiMo는 **설정 파일에서 공존할 뿐 완전히 독립적**이다.

```
┌─────────────────────────────────┐
│  ~/.kimi/config.toml            │
│                                 │
│  [providers.mimo]               │     [services.moonshot_search]
│  → Xiaomi API                   │     → Kimi Code API
│  → MiMo 모델 응답 생성          │     → 웹 검색 결과 반환
│  → MiMo 자체 quota              │     → Kimi Code 계정 search quota
│                                 │
│  default_model = "mimo-v2.5-pro"│
└─────────────────────────────────┘
         파이프라인 A                    파이프라인 B
        (완전 독립)                    (완전 독립)
```

| 항목 | MiMo (모델) | SearchWeb (서비스) |
|------|-------------|-------------------|
| 제공자 | Xiaomi (小米) | Kimi Code (Moonshot) |
| API | `token-plan-sgp.xiaomimimo.com` | `api.kimi.com/coding/v1/search` |
| 인증 | MiMo API 키 | Kimi Code OAuth |
| Quota | MiMo 자체 quota | Kimi Code 계정 search quota |
| 실패 시 | LLM 응답 불가 | 웹 검색 불가 (모델 응답은 정상) |

## 4. 조사 과정 (Evidence Chain)

| # | 조사 내용 | 결과 | 상태 |
|---|----------|------|------|
| 1 | `~/.kimi/oauth/` 디렉토리 확인 | 미존재 | ❌ (초기) |
| 2 | config.toml services 섹션 확인 | `api_key = ""`, OAuth 설정 존재 | ⚠️ |
| 3 | Context7 공식 문서 조사 | "SearchWeb depends on external services, only provided by Kimi Code platform" | 📖 |
| 4 | `kimi login` 실행 | OAuth 토큰 발급 성공 | ✅ |
| 5 | `~/.kimi/credentials/kimi-code.json` 확인 | access_token, refresh_token 유효 | ✅ |
| 6 | SearchWeb 재시도 | 여전히 403 | ❌ |
| 7 | `curl` 직접 호출로 에러 메시지 확인 | `access_terminated_error` — quota 소진 | 🔴 **근본 원인** |

## 5. 해결 상태

| 방법 | 상태 | 비고 |
|------|------|------|
| OAuth 인증 | ✅ 완료 | `/login` → Kimi Code 선택 |
| default_model 복원 | ✅ 완료 | `mimo-v2.5-pro`로 복원 |
| SearchWeb quota 리셋 | ⏳ 대기 중 | 다음 결제 사이클에 자동 리셋 또는 플랜 업그레이드 |

## 6. 교훈

- `403` ≠ 인증 실패. `access_terminated_error`는 quota 소진이다.
- 모델(provider)과 서비스(services)는 config.toml에서 공존하지만 **아키텍처적으로 완전히 독립적**이다.
- MiMo quota와 SearchWeb quota는 별개의 파이프라인이다.
- `kimi login` 실행 시 `default_model`이 자동 변경되므로 주의 필요.
