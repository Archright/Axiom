# E3 측정 계약 — J3 test-supply 캐리어의 GO-critical 소요 효과 (2026-10-11)

> **종류**: 측정 계약 (measurement contract) — 읽기 전용 관측 규약. 코드 변경·게이트 변경·판정 의미 변경 없음.
> **성격**: **확증적(confirmatory) 데이터를 관측하기 전에** 고정된 계약이다 (no-peeking rule). 이 문서의 병합 OID가 fixation point다.
> **측정 대상**: `admission-gate` 런의 `attest / admission-check` job 내 GO-critical 스텝 소요 (`[check] GO-critical …`, 정의는 §5.1).
> **측정 근거**: 2026-10-10/11 조사에서 **실측(measured)** 된 사실들 — 본 문서는 이를 재유도(re-derive)하지 않고 인용한다.
> **소비처**: 캐리어(PR #721) 효과의 인과적 입증 여부 판정. 제품 판정(judgment) 권위는 전혀 변경되지 않는다 (§9).

---

## 1. 목적과 범위 (Purpose + Scope)

PR #721 (J3 test-supply 캐리어)는 착지했고 작동한다 — 그러나 그 **성능 효과는 아직 인과적으로 입증되지 않았다**. 2026-10-10/11 조사는 (a) 개입이 공급(side)에 실제 효과를 냈음을 확인했고, (b) 핵심 교란 후보들을 배제했으며, (c) 독립 속도 공변량을 발견했고, (d) 검정력 산술을 정정했다. 이 문서는 **추가 확증 데이터를 하나라도 보기 전에** 분석 규약을 고정한다 — 관측 후 규약을 고정하면 탐색적 선택이 확증적 주장으로 위장된다(§0.9 극장).

- 본 문서는 **읽기 전용 측정 계약**이다. 소스 코드·워크플로·게이트·판정 의미를 변경하지 않는다.
- 판정 권위는 전혀 건드리지 않는다: merge-admission의 authority는 GitHub이며(AGENTS.md §2.3), Axiom 게이트·판정 의미는 이 계약과 무관하다(§9).
- 이 계약은 새 authority를 만들지 않는다(§2.6 authority_invariant_protocol) — 기존 관측면(GitHub Actions API + job 로그)을 소비하는 **분석 규약**일 뿐이다.
- 본 문서 자체가 no-peeking 규칙의 집행 수단이다: §5의 고정 사항(추정량·성공 기준·δ의 의미·층화·n·중지 규칙)은 확증 데이터 관측 전에 병합되어야 효력이 있다.

**용어 주의**: 이 문서에서 "B-코호트/C-코호트"는 **처치군/대조군(arm)** 이다. `AXIOM_CACHE_B_VERIFY`·`B_PROBE`의 "B"는 **CI 캐시 층(B-cache)** 이다. 둘을 혼동하지 않는다.

## 2. 개입과 측정된 공급 효과 (사실 A — 전부 실측)

`Makefile`의 `test-fast-one`이 `--nimcache:build/nimcache/test`를 얻었다 (PR #721, merge `2ea11a3a`, 2026-10-11). 이전에는 `config.nims`의 `else` 분기가 테스트 컴파일을 `build/nimcache/debug`로 보냈고, `build/nimcache/test`는 존재하지 않았다. 측정된 증거:

- **격리 워크트리 재현 (수정 전)**: `build/nimcache/debug` 262 파일, `test/` 부재. **수정 후**: `test/` 227 파일.
- **시딩 런 `38094240091` 아티팩트 ZIP 인벤토리**: `ci-compile/` 1,693 + `test/` **315** + `debug/` 148.
- **착지 후 재사용 런 `38096084992`**: `[test-supply] restored build/nimcache/test entries=315` + `AXIOM_CACHE_B_VERIFY: RESULT OK — 5/5` + `B_PROBE: OK` ×5.

즉 개입의 **공급 효과(supply effect)는 실측으로 확정**됐다: 테스트 nimcache가 CI를 통해 저장·복원된다(315 엔트리 일치). 본 계약이 입증하려는 것은 그 다음 단계 — **소요(duration) 효과**다.

## 4. E-0b 공변량 후보 평가 (사실 D — 전부 실측)

### 4.1 조건 정의

공변량 후보는 다음 여섯 조건을 모두 만족해야 채택된다. 앞 다섯은 계약 고정 **이전**에 평가 가능한 자격 조건이고, 여섯째는 분석 기능 조건이다:

1. **Result-independence** — 공변량 값이 측정 결과(GO-critical 소요)에 의해 결정되지 않을 것.
2. **Treatment-independence** — 처치 arm(캐리어 HIT/MISS)이 공변량 값을 바꾸지 않을 것.
3. **Repeatability** — 동일 조건에서 값이 반관측 가능하고 층을 정의할 수 있을 것 (런마다 고유 id는 층이 될 수 없음).
4. **B/C overlap** — 두 arm 모두에서 해당 공변량의 관측 지지(support)가 존재할 것.
5. **Pre-fixation** — 계약 고정 시점 이전 데이터만으로 평가·채택되었을 것 (확증 결과에 대한 선택 금지).
6. **Residual-variance reduction** — 실제로 결과의 잔차 분산을 유의하게 줄일 것.

## 5. 고정 측정 계약 (fixation — 본 문서의 핵심)

이 절의 모든 항목은 확증적 C-코호트 데이터 관측 **이전에** 고정되며, 병합 후 변경은 계약 위반이다(변경 필요 시 새 계약 문서로 개정 — §0.12 계약 명시 개정).

### 5.1 추정량 (estimand) — Δ 채택, Δ* 기각

**1차 추정량: Δ = μ_B − μ_C** — 런 단위 GO-critical 스텝 소요(초)의 B-arm(캐리어 HIT) 평균에서 C-arm(캐리어 MISS) 평균을 뺀 값. 양수 = 캐리어가 GO-critical을 단축.

**GO-critical 스텝 정의**: `admission-gate` 런의 `attest / admission-check` job에서 이름이 `[check] GO-critical`로 시작하는 스텝 구간 (선행 계약: `docs/evidence/go_critical_test_cost_2026-10-08.md` — `.github/workflows/admission-check.yml:751`, DEBT#432 4종 테스트, `make test-fast-one` 4회 순차 — 컴파일 포함이 어드미션 경로의 실비용 정의). 다중 매치 시 합산. 관측 스케일(실측): fast 295/347 s, slow 544–550 s.

**Δ* (공통 속도 분포로 표준화) 기각 이유**: 표준화는 속도 공변량→소요 변환 모형을 요구한다. 그 모형을 추정할 수 있는 데이터는 n=8 (fast 2건)뿐이며(§4.2), 모형 선택 자체가 연구자 자유도를 늘려 no-peeking 규율을 약화시킨다. 반면 고정 임계 층화(§5.2)는 비모수적이고 모형 가정이 없다. 검정력 산술(§5.5)도 혼합 σ 기준으로 이미 완결되어 있다.

**단위·정밀도**: 초, 소수 첫째 자리. 추출은 로그 라인 타임스탬프(7자리 소수) 기준(§7.2).

### 5.2 층화 (stratification) — `a-restore duration_ms`, 임계 40 s, 마커로만

- 층화 변수: `a-restore duration_ms` (`##[end-action id=__self.a-restore …duration_ms=…]`, A층 고정비 툴체인 복원).
- **임계값 40,000 ms — 사전(a priori) 고정.** H층(high) = >40 s (실측 fast 표현형), L층(low) = ≤40 s (실측 slow 표현형).
- 역할은 **마커**: 잠재 러너/스토리지 클래스의 대리 표지일 뿐, 캐리어 효과의 인과 경로가 아니다(§4.2 단서). 해석문에 인과 언어 금지.
- **1차 분석**: 층별 Δ̂_H, Δ̂_L 각각의 편측 95% CI + 표제 Δ̂ = 층별 Δ̂_s의 가중평균, 가중치 = **달성 표본비례** (n_s/(n_B+n_C) — 결과값이 아닌 카운트만의 기계적 함수이므로 peeking 아님).
- **민감도 분석 (사전 등록)**: 임계 35 s / 45 s 재계산 + 비층화 Δ̂. 1차 판정의 부호(Δ̂ > 0)가 전 변형에서 일치해야 주장 유지; 불일치 시 주장을 1차 추정량으로 제한하고 불일치를 공개.
- 층화가 실패하는 경우(L층 또는 H층이 한 arm에서 공층) — 그 층의 추정은 불가로 보고하고, 주장은 관측된 층으로 제한.

### 5.3 표본 단위와 블록 부트스트랩

- **표본 단위 = 1개 `admission-gate` 런.**
- **의존성**: 같은 키 세대(key generation/시드 수명)를 공유하는 런은 독립이 아니다. 실측: 관측 창 ~2.6 h에 4회 로테이션; 세대 `2148f712/090df7f1` 하나가 4/4 연속 런을 커버 — 즉 독립 세대 수는 런 수보다 훨씬 적을 수 있다.
- **규칙**: 분석 시 확인 집합의 **독립 세대 수 G를 keygen 로그에서 기계적으로 집계해 보고**한다(arm별로도). 추론 CI는 **세대-수준 블록 부트스트랩**(세대를 재표본 단위로, arm 내 재표집, B=10,000회, 백분위 편측 95% 하한)으로 산출한다. 런-수준 독립 가정 부트스트랩은 금지.
- **퇴화 규칙**: 어느 arm의 세대 수가 2 미만이면 세간 부트스트랩이 퇴화한다 → 그 arm의 결과는 "단일 세대 관측"으로 표기하고 세대 일반화 주장 없이 보고.

### 5.4 포함 기준 (기계적, 사전 고정)

- 공통: `admission-gate` 워크플로, `attest / admission-check` job, conclusion `success`, 로그 보존 완료, 개입 병합(`2ea11a3a`) 이후 코드에서 실행된 런.
- **B-arm**: `[test-supply] restored build/nimcache/test entries=…` + `AXIOM_CACHE_B_VERIFY: RESULT OK` + `B_PROBE: OK` 로그로 HIT 기계 확인. n_B = 12 (조사가 확보한 표본; 구성 전수 감증을 분석 시 수행 — 각 런의 HIT 증거와 개입 이후 코드 여부를 기록). **구성 감증 규칙: 개정 기록 A1(문서 말미) — 소요 사전관측 런 제외(fail-closed).**
- **C-arm**: 캐리어 비복원(MISS) 기계 확인 — test-supply 복원 라인 부재 또는 대응 cache-not found 증거. n_C = 30 (§5.5). 이벤트 유형(merge_group/pull_request)은 런별 기록하고 균형을 보고한다(요구값을 정하지 않는다).
- 감증 실패 런은 사유와 함께 제외·기록하고, 유효 n이 채워질 때까지 수집 계속 (기준 기반 — 결과값 기반 제외 아님).
- 결측 규칙: 로그 소멸 등으로 추출 불가한 런은 제외·기록; 대체(imputation) 없음.

### 5.5 검정력 — 부등-n 공식과 3단계 실현가능성 판정

**공식 (조사 산술 그대로)**: `δ / (σ·√(1/n_B + 1/n_C)) ≥ z_crit`, n_B = 12, z_crit = 2.8016 (편측 α ≈ 0.0025 — 정규 분위수 산술).

σ(GO-critical 혼합)별 필요 n_C — **실측 산술 표 (사실 E, 정정값)**:

| σ | 필요 n_C |
|---|---|
| 123 s (혼합 실측) | **유한 해 없음** (n_C→∞에서 max z = 2.760 < 2.8016 — 98 s 효과 검출 불가) |
| 121 s | ≈ 4,162 |
| 120 s | 611 |
| 115 s | 109 |
| 110 s | 57 |
| **102.4 s** | **30** |

층화 적용 시 층 내 σ ≈ 2.1 s (slow 코호트 sd) → 설계가 자명히 실현가능해지지만, **그 σ는 소표본 추정치**다(§4.2 단서).

**3단계 판정 (고정)**:

1. **수학적**: 조건부 PASS — n_B=12, δ=98 s, z_crit=2.8016에서 유한 n_C가 존재할 필요충분조건은 σ ≤ 102.4 s (n_C=30). σ ≥ 123 s면 어떤 n_C로도 불가.
2. **통계적**: PROVISIONAL — 비층화 σ̂ = 123 s는 FAIL; 층화 σ̂ ≈ 2.1 s는 PASS이나 소표본(n=8, fast 2건) 추정 → **확증 데이터 전까지 UNVERIFIED**. 중요: σ 재추정으로 n을 바꾸는 것은 peeking이므로 금지 — n은 σ와 무관하게 아래 고정값으로 고정된다.
3. **운영적**: PASS (구속 조건 포함) — C-arm(MISS) 샘플은 자연 재생된다: 키 로테이션이 ~2.6 h당 ~4회 발생하고 각 세대는 시딩(30–45분) 전까지 MISS 런을 낳는다. B-arm은 확보됨(n=12, §5.4 감증 대기). 수집은 고정 n까지이며 조기 분석 없음(§5.6).

### 5.6 no-peeking — 고정 n과 중지 규칙

- **고정 n: n_B = 12, n_C = 30** (σ=102.4 s 행에서 유도된 보수적 계획값 — §5.5 표). 층화 σ가 실제로 작으면 달성 검정력은 계획을 초과한다(해로움 없음).
- **단일 분석**: 유효 n_B=12 ∧ n_C=30 도달 시점에 **딱 한 번** 결과 추출·분석 수행. 결과 추출은 스크립트 단일 패스로 수행하고 반복 추출 금지.
- **중지 규칙**: (a) 정상 종료 = 고정 n 도달 즉시 분석. (b) 창 닫힘 종료 = 본 문서 병합 후 30일(계약 파라미터) 경과 시점에 유효 n 미달이면, 달성 n으로 **"underpowered, non-confirmatory"** 명기 분석 1회 허용 — 주장 상향(§5.7 Tier 2) 불가, Tier 1도 하한이 0을 넘어야만 "개선" 서술 가능. (c) 중간 분석(interim) 금지 — HIT/MISS 여부·세대 라벨 같은 **포함기준 확인**은 허용하되 기록하며, GO-critical 소요값 추출은 아니다.
- 포함기준 확인(§5.4)은 결과 분포를 드러내지 않는다 — HIT/MISS 상태와 세대 귀속은 설계 변수다.

### 5.7 성공 기준과 δ의 의미 (고정)

- **δ = 98 s. 의미 = "입증해야 할 최소 개선" (confirmatory claim threshold)** — 검정력 계획용 숫자가 아니다. 같은 값이 계획 효과 크기로도 쓰이는데(§5.5 표의 유도 행), 이 이중 사용은 여기서 명시 선언된다: n은 이 δ로 계획되지만, δ가 주장으로 승격되는 유일 경로는 아래 Tier 2 통과다. 출처: 사실 E의 검정력 산술이 운반하는 효과 크기 (관측 fast/slow 코호트 간격 295/347 vs 544–550 s 스케일과 정합).
- **Tier 1 "improvement"**: 층화 Δ̂의 편측 95% CI 하한 > 0 → "캐리어가 GO-critical을 개선" 주장 허용.
- **Tier 2 "at least δ"**: 같은 하한 > 98 s → "98 s 이상 개선" 주장 허용. Tier 1만 통과 시 "개선(크기 미정)"까지만.
- 추론 CI는 §5.3 블록 부트스트랩 하한(1차)으로 하며, 계획용 z_crit=2.8016은 n 산출에만 쓰인다.
- 민감도 변형(§5.2)은 서술용 — 추가 주장 표면 없음.

## 6. 파일럿 격리 기록 (사실 F)

계약 고정 **이전**에 이미 관측된 C-코호트 데이터 — HIT 1건 `38096084992` + MISS 3건 `38094240091`, `38098772060`, `38099113170` — 는 **탐색적 파일럿으로 분류**되며, 확증 통계에서 **완전 배제**된다. 파일럿이 기여한 것은 설계 변수뿐이다: 층화 임계 유도에 쓰인 a-restore 8-표본(§4.2), σ 추정치(§5.5), δ 스케일. 파일럿 런 4건은 확증 집합에 어떤 관측치로도 기여하지 않으며, 확증 C-arm은 고정 **이후** 런으로만 채운다(§5.4).

## 7. Wall-clock 정의와 측정 정밀도 (사실 G·H — 전부 실측)

### 7.1 Run-level wall-clock (G)

- **채택**: `updated_at − run_started_at` — UI 표시값과 동일. 관측 8런 전체에서 job 유도값보다 **3–5 s 크다** — 두 정의를 혼용 금지.
- **금지**: `GET /actions/runs/{id}/timing` — GitHub 공식 발표 기준 "in the process of closing down". 어떤 수치와도 이 엔드포인트를 사용하지 않는다.
- 역할: run-level wall-clock은 **부수 서술자**다. 1차 추정량(§5.1)은 스텝 수준이며 두 수치를 상호 변환하지 않는다.

### 7.2 추출 정밀도 (H)

- API `steps[].started_at/completed_at`은 **초 해상도**; 로그 라인은 **7자리 소수 초**를 운반한다.
- **규칙: 모든 측정값은 로그 라인에서 추출한다.** API 스텝 타임스탬프는 로그 소멸 등 불가피한 경우의 fallback이며, 사용 시 정밀도 손실을 표기한다.
- 이 구분이 실질적인 곳: 관측 범위 37.2 s인 프록시 메트릭 — 초 해상도에서는 이 범위의 미세 구조가 사라진다.

## 개정 기록 A1 — n_B=12 구성 감증의 fail-closed 규칙 (2026-10-11)

> **성격**: §5.4에 이미 존재하는 감증-제외-수집-계속 메커니즘("감증 실패 런은 사유와 함께 제외·기록하고, 유효 n이 채워질 때까지 수집 계속")의 **fail-closed 정의를 명문화하는 문서 개정**이다. §5의 고정 설계값 — 추정량(§5.1), 층화(§5.2), n_B=12·n_C=30(§5.5–5.6), δ·Tier(§5.7), 중지 규칙(§5.6) — 은 **일절 변경하지 않으며**, 포함 조건을 완화하는 방향이 아니라 **축소만 하는 단방향 개정**이다(AGENTS.md §0.12 계약 명시 개정; 판정 의미·게이트·authority 불변 — §8·§9).

### A1.1 동기 (비대칭)

조사는 계약 고정(병합 `ad43e67fa`, 2026-10-11T02:52:14Z) **이전**에 8런의 GO-critical 소요를 관측·기록했다(§4.2 a-restore 8-표본: fast 295/347 s, slow 544–550 s; §5.1 관측 스케일과 동일 집합). §5.4의 n_B=12는 "조사가 확보한 표본"이며 그 구성은 런 ID로 열거되어 있지 않다. 이 소요-관측 런 중 하나라도 확증 n_B에 남아 있으면, **결과값(소요 표현형)의 사전지식이 확증 집합에 유입**된다. C-arm에는 §6이 "확증 C-arm은 고정 이후 런으로만 채운다"는 엄격 규칙을 두지만, B-arm에는 동일한 규칙이 없어 양 arm이 비대칭이다.

### A1.2 규칙 (fail-closed)

확증 n_B 구성 감증(§5.4 "감증 대기" 항목의 집행)은 다음을 따른다:

1. **열거**: 후보 런 전수를 run ID·`run_started_at`·HIT 증거와 함께 열거한다 (E-4/E-5 수집 리저 `data/e4e5/`가 기계적 토대를 제공한다 — 단, §5.6(c)에 따라 **GO-critical 소요값의 중간 추출은 하지 않는다**).
2. **소요 사전관측 런 제외**: GO-critical 소요가 고정 시점 이전에 관측·기록된 런(§4.2의 8-표본 집합과 그 외 조사 과정에서 소요가 기록된 모든 런)은 확증 n_B에서 **제외**한다.
3. **판별 불가 = 제외 (fail-closed)**: 후보 런이 소요 사전관측 집합의 멤버인지 판별할 수 없는 경우(조사 기록에 run ID 미열거 등)에도 **제외를 기본값**으로 한다. "제외되지 않음을 증명 못 하면 제외"다.
4. **기록·대체**: 제외 런은 사유와 함께 기록하고 §5.4의 기존 메커니즘대로 유효 n_B=12가 채워질 때까지 수집을 계속한다. 대체 런은 고정 이후 런을 우선한다.
5. **경계 유지**: 소요가 관측되지 않은 사전고정 런의 보류 여부는 본 개정이 새로 금지하지 않는다 — §5.6이 이미 허용한 설계 변수 확인(HIT/MISS·세대 귀속)만으로 선별된 런은, 소요 사전관측이 아니라면 제외 대상이 아니다 (2·3 항의 소요-사전관측 런만이 대상이다).

### A1.3 근거

- **no-peeking (§1, §5 서문)**: 소요 관측은 결과값 사전지식이다. §5.6은 포함기준 확인(HIT/MISS·세대)을 "결과 분포를 드러내지 않는" 허용 행위로 한정하며, 소요 추출은 단일 분석 시점까지 금지된다 — 소요가 이미 관측된 런의 확증 포함은 이 규율의 정신 위반이다.
- **§6 대칭성**: C-arm은 파일럿 4런을 완전 배제하고 고정 이후 런만 취한다. B-arm의 결과값 사전지식 런에 동일 취급을 적용하는 것이 대칭이다.
- **§0.9 극장**: "구성 감증 대기" 상태에서 소요-사전관측 런이 조용히 확증 집합에 남는 것은 탐색적 선택의 확증 위장(극장)이다 — 본 개정은 그 경로를 집합 규칙 수준에서 봉쇄한다.
- **단방향성**: 제외만 가능하고 포함 완화는 불가능하므로, 이 개정으로 고정 이후 이미 관측된 확증 데이터의 해석이 개선되거나 바뀔 여지가 없다 (개정의 소급 왜곡 없음).

### A1.4 검증 가능성

구성 감증의 실행 기록은 `data/e4e5/` 수집 리저에 run ID 단위로 남는다(수집 도구 `tools/ci/e4e5_collect.sh` — 키·세대 귀속과 고정-이후 여부를 기계 기록). 본 개정은 읽기 전용 측정 규약의 문서 개정으로, 어떤 코드·워크플로·게이트도 변경하지 않는다 (§8 범위 밖 선언 유지).
