## 1. Why 5 legs: the measured partition balance

The shard partition is a size-greedy / longest-processing-time placement over
`git ls-tree -r -l HEAD` blobs, minus the ScanCode `ignores_VCS` basenames — the
same filter the merge step's expected-set derivation uses. Replaying that exact
pipeline on the HEAD tree — the filter is the workflow's own `ls-tree` awk, and
the placement is the workflow's own `-v n=` awk:

```
LIST=$(git ls-tree -r -l HEAD | awk '
  NF != 5 || $5 ~ /"/ { exit 1 }
  tolower($5) !~ /(^|\/)(\.bzr|\.bzrignore|\.git|\.gitignore|\.gitattributes|\.hg|\.hgignore|\.repo|\.svn|\.svnignore|\.tfignore|vssver\.scc|cvs|\.cvsignore)$/ {print $4, $5}')

# per leg, for N in 3 5 and S in 0..N-1:
printf '%s\n' "$LIST" | LC_ALL=C sort -k1,1rn -k2,2 \
  | awk -v s=$S -v n=$N 'BEGIN{for(i=0;i<n;i++)w[i]=0}
      {m=0;for(i=1;i<n;i++)if(w[i]<w[m])m=i;w[m]+=$1;if(m==s){c[s]++;b[s]+=$1}}
      END{printf "shard %d: %6d files %8.1f MB\n", s, c[s], b[s]/1048576}'
```

| n | per-leg files | per-leg bytes |
|---|---|---|
| 3 | 2345 / 2271 / 2272 | 29.7 MB / 29.7 MB / 29.7 MB |
| 5 | 1362 / 1362 / 1438 / 1363 / 1363 | 17.8 MB each |

Scan surface total: **6,888 files, 89.2 MB**.

The 3-partition already balances bytes perfectly, so byte balance is not what
the expansion buys. What it buys is the per-leg file count and byte volume that
one ScanCode invocation has to walk: 2,271–2,345 files / 29.7 MB on the slowest
leg becomes 1,362–1,438 files / 17.8 MB. The merge job's critical path is set by
the slowest leg, so the reduction is roughly 40% per leg at unchanged total
work. The 5-way split's spread (76 files, 1,362–1,438) stays small enough that
the extra leg does not reintroduce a straggler.

## 2. The dead duplicate-path guard

The pre-change merge step read the **merged** report and then asserted no
duplicate paths:

```
jq -s '{ ... files: (map(.files) | add | sort_by(.path) | group_by(.path) | map(.[0])) ... }' \
  $SHARD_REPORTS > "$RUNNER_TEMP/scancode.json"
jq -r '.files[] | select(.type=="file") | .path' "$RUNNER_TEMP/scancode.json" | sed ... > merged_paths.txt
if [ "$(LC_ALL=C sort merged_paths.txt | uniq -d | wc -l)" -ne 0 ]; then ... exit 1; fi
```

`group_by(.path) | map(.[0])` collapses every repeated path to exactly one
entry, so `merged_paths.txt` is already unique and `uniq -d` is empty for every
possible input. The check could not fire. It was theater by construction: the
step advertised a cross-shard duplicate guarantee it did not enforce (AGENTS.md
§0.9).

Repair: the guard now runs on the **raw** per-shard reports, before the merge
jq, so a path emitted by two shards is observable:

```
jq -r '.files[] | select(.type=="file") | .path' $SHARD_REPORTS \
  | sed "s|^${PFX}/||" | LC_ALL=C sort | uniq -d > "$RUNNER_TEMP/dup_paths.txt"
if [ -s "$RUNNER_TEMP/dup_paths.txt" ]; then ... head -20 ...; exit 1; fi
```

FILE entries are disjoint by the partition, so a duplicate is a real
split/merge defect. DIRECTORY entries are legitimately emitted once per shard
and the merge's per-path dedup is what restores single-scan shape for them —
that path is unchanged and is pinned by a passing fixture.

## 3. The zero-shard silent death

The shard count was read with `grep -c`:

```
SHARD_COUNT=$(printf '%s\n' "$SHARD_REPORTS" | grep -c .)
```

`grep -c` exits 1 on zero matches. Under `set -euo pipefail` inside a command
substitution, the assignment aborts the step at that point, so an empty shard
directory — a failed or cancelled matrix leg — produced a **bare exit 1 with no
message at all**. The diagnostic on the next line never ran.

Repair: the count comes from a construct that always exits 0, leaving the
explicit assertion as the single deciding point:

```
mkdir -p "$S"
SHARD_COUNT=$(printf '%s\n' "$SHARD_REPORTS" | awk 'NF{c++} END{print c+0}')
[ "$SHARD_COUNT" -eq 5 ] || { echo "expected 5 shard reports, found $SHARD_COUNT" >&2; exit 1; }
```

`|| true` is deliberately **not** used: `bin/anti_theater_gate` rules that
construct out as CI Theater on `.github/workflows/**` (rule C in
`src/gate/runners/anti_theater_gate.nim`), and it would also defeat `set -e`
rather than restore the assertion's reachability.
