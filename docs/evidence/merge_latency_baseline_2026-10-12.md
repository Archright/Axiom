## 7. 측정 경계 기록 (반드시 아는 한계)

1. **Σdur/Σgaps 분할의 ±3.8 s 시프트**: 본 하니스는 사전 계약대로 API `started_at`/`completed_at`(초 반올림)을 쓴다. 등록 감사치(827.2/16.9)는 작업 경계를 로그 라인(7자리 소수, E3 §7.2)에서 잡은 값으로, 경계당 ~0.5 s가 gaps로 이동한 분할이다. **dur+gaps 합(망원합)과 wall·residual은 양쪽이 정확히 일치**하므로 비교 연산(Δ 비교)에는 영향이 없다. 경계 로그 파싱 채널이 필요해지면 본 문서를 개정하지 말고 새 증거 문서로 등록한다.
2. **residual의 의미**: 시작 오프셋(run_started_at→첫 job) + 종료 오프셋(마지막 job→updated_at)의 합. 관측 범위 1–5 s로 안정 — 이 범위 이탈은 job 세트 변화(예: 신규 직렬 단계 삽입)의 1차 신호다.
3. **failure-conclusion 런 3건**: 운영 wall에 계수(등록 집합 정의). 비교 시 conclusion 필드로 투영 분리 가능. "EXECUTED" 분류는 **소비 job(attest/admission-check) 성공** 기준이며 런 전체 conclusion과 독립이다.
4. **API 초 해상도**: E3 §7.2의 7자리 로그 채널이 필요한 정밀 판정(E3 Δ̂ 확증 분석)은 본 하니스 소비 대상이 아니다 — A2.3.4 방화벽 유지.
