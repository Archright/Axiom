## §2. 계약 6종 (Phase C 구현이 반드시 충족할 불변식)

### 2.1 입력 계약
job2a는 **GO-lane 산출물을 소비하지 않는다**(감사 §3 확증의 보존). 소비 입력 전체:
- job1(`build-base-artifacts`) artifact(B-tree 산출물·bin/ax materialize — run-scoped 이름 그대로)
- Checkout B(베이스)·Checkout H(헤드)·이벤트 페이로드·B draft·vault manifest
- `needs: [build-base-artifacts]` 엣지 추가는 허용되는 유일한 신규 의존(데이터 의존 실재).

### 2.2 출력 계약
- **값 채널(잡 outputs)**: identity 스텝의 `$GITHUB_ENV` 산출값 중 잔여 잡이 소비하는 것 — B·H·tree OID, SUBJECT_HEAD, SUBJECT_ID. 한도 공식 문서 기준 **1MB/잡·50MB/run**(소형 값만 — 대형 값의 outputs 사용 금지).
- **파일 채널(artifacts)**: `draft-assembled.json`·`evidence/<sid>.json`(전방 상태 체인 파일). 신규 artifact 이름은 **기존 identity 계약 형식**을 따른다: `admission-independents-<candidate head>-<run_attempt>`(`admission-check.yml:118-130` 계약 + v4+ immutable·재시도 충돌 방지 — `github.run_attempt` 접미는 현행 관례 :56-59·:119-128 준수).
- **존재 계약**: job2a는 잔여 잡 소비 산출물을 **성공 시에만** 업로드한다(실패 시 부분 산출 업로드 금지 — 잔여 잡의 다운로드 fail-closed와 정합. lane artifact의 `always()` 업로드 관례(:3629-3649)와 달리, job2a 산출은 "GO 실패 시에도 재사용 가능한 PASS 재료"가 아니라 잔여 잡의 소비 입력이므로 부분 상태를 전달하지 않는다).

### 2.3 동일성 계약
잔여 job2는 job2a 산출 소비 시점에 **run·tree·attempt identity를 전부 재검증**한다:
- artifact 이름 임베디드 `<candidate head>` == `github.event.pull_request.head.sha || github.event.merge_group.head_sha || github.sha`(현행 판별자와 동일 기준)
- 소비 산출의 run identity == 자기 run(`github.run_id`), attempt 일치(§3 ⑤의 부정시험 대상)
- **불일치·누락·중복(동일 판별자 2개)·stale = red** — 성공 아님(AGENTS.md §0.9 fail-closed).

### 2.4 실패 계약 (skipped=Success 플랫폼 시맨틱 대응)
공식 문서 확정(2026-11-03, docs.github.com required-status-checks troubleshooting·SA-2 검증): **"Successful check statuses are success, skipped, and neutral" — skipped 잡은 Success로 보고되고 병합을 차단하지 않는다.** 따라서:

1. **needs 기본 전파만으로는 fail-closed가 성립하지 않는다** — GO lane 실패 시 종속 잡이 skip되면 "Success"로 보고되어 merge queue가 배치를 통과시킨다(유일한 무료 차단은 미보고=Pending뿐 — 의존 불가).
2. 잔여 job2는 `if: ${{ !cancelled() }}`로 생존한다(bare `always()` 금지 — 취소 진행 중에도 실행되는 공식 경고; 현행 `:702` `if: always()`는 이 계약으로 정합 교체 — 취소 상태에서의 실행은 요구하지 않는다: cancelled ∉ 성공 집합이므로 취소된 배치는 어차피 병합 불가).
3. **가드 스텝(잔여 잡 최초 스텝)**: `needs.build-base-artifacts.result`·`needs.go-critical-lane.result`(matrix 통합 result)·`needs.job2a.result`가 **전부 `'success'`인지 명시 검사** — failure·cancelled·skipped 어느 하나라도 아니면 exit 1(명시 판정 라인 출력 — ADR-0032 (f) 극장 관측점 형식 준수).
4. 판정 신호는 `needs.<id>.result` 기준(outputs은 실패·skip 시 비어 있음 — 공식 예시 기반, 값 존재에 의존 금지).
5. 기존 fail-closed 장치(artifact 다운로드 실패→red·lane decision 파일 검증·GO cross-check 환경 강제)는 전부 잔여 잡에 잔류 — 가드는 추가이지 대체가 아니다.

### 2.5 witness 계약
- witness(`Attest witness-only` 포함 일체)는 **잔여 job2에 잔류** — `GO_TESTED_TREE_OID`(:1739-1741)·`judgment-decision*.json` 소비(:1812-1854)·"실패한 lane이 재사용 가능 PASS record를 mint하지 못하게 함" 존재 목적(:1554-1567) 불변.
- mint 시작 = 잔여 잡 종료 후(caller `:464-471` 소비 계약 불변) — **mint 지연은 증가하지 않는다**(잔여 잡 종료 시각이 병렬화로 늦어지지 않는 한 — §4 관측 항목).

### 2.6 운영 계약
- **5개 필수 check(admission-check·bsec-integrity·debt-registry-gate·generation-acceptance·axiom-operational-slice)·ruleset required 집합·bypass 상태 불변** — 병합 판정 의미론 0 변경.
- callee의 4잡 구조는 5잡이 된다(build-base · go-critical-lane · **job2a** · admission-check) — caller 8잡·5-leg 구조 불변.
- 기존 스텝 이름·artifact 이름·attempt suffix는 **바이트 수준 불변**(§6 판정 참조).

## §3. 부정시험 (상태별 parameterized — 구현 승인의 필수 통과 조건)

**공식 문서 전제(SA-2)**: skipped=Success 병합 미차단·cancelled ∉ 성공 집합·needs 기본 전파는 skip. **부정시험의 핵심 목적은 §2.4 가드가 플랫폼 시맨틱을 실제로 이기는 것의 입증이다.**

격자(전 잎이 **red/거부**여야 한다):

| # | 시나리오 | 기대 관측 |
|---|---|---|
| ①a | GO lane **실패** + job2a 성공 | 가드 red → 잔여 잡 FAILURE → admission-check check red → 배치 통과 불가 |
| ①b | GO lane **skip** + job2a 성공 | 동일(①b가 §2.4의 존재 이유 — skip이 Success로 마스킹되지 않는지 입증) |
| ①c | GO lane **취소** | 잔여 잡 `!cancelled()`로 미실행 또는 가드 red — 어떤 경로든 check가 success로 보고되지 않음 |
| ②a | job2a **누락**(artifact 부재) | 다운로드 실패 → 잔여 잡 red |
| ②b | job2a **skip** | 가드 red |
| ②c | job2a **취소** | ①c와 동일 원칙 |
| ③ | tree identity 불일치(위조 head·tree OID) | 동일성 재검증 red |
| ④ | 타 run/세대 산출 재사용(위조 run_id) | 동일성 재검증 red |
| ⑤ | **run attempt 불일치**(재시도 산출 소비) | attempt 재검증 red |
| ⑥ | GO 실패 상태에서 witness가 재사용 가능 PASS mint 발행 | **발생 불가**(witness 계약 2.5 — 코드 경로 부재를 구현 리뷰로 입증 + ①a 관측으로 확증) |

**실행 방식(동결)**:
- **(a) 결정적 테스트**: §2.3·§2.4 재검증·가드 로직은 위조 입력에 대한 자동화 테스트로 전 잎 상태를 입증(잎 상태 = needs result 문자열 {failure, skipped, cancelled, success} × 산출 {정상, 누락, 불일치, 타 run, 타 attempt} — 로직이 임의의 조합에서 red인지 파라메터화 검증).
- **(b) 실전 음성 대조 ≥1건**: scratch PR(선례 #1041 — check FAILURE + isRequired=true + mergeStateStatus BLOCKED, 미병합 종료)로 ①a 계열(실제 GO 실패 유발)을 큐 경로에서 관측 — 배치 실패·PR 큐 제거·타임라인 사유 기록까지. merge-queue 저장소에서 GO는 merge_group에서만 실행되므로(ADR-0032 (b)) 실전 ①a는 큐 배치 1건 소비가 필요하다(비용 인지·기록).
- **판정**: (a) 전 잎 red + (b) 관측 성립 — 하나라도 아니면 구현은 착지하지 않는다(극장 금지, 즉시 중단·보고).

## §4. 효과 게이트 동결 (no-peeking — 착지 이후 신규 관측만)

**동결 시점**: 본 문서 착지(구현 이전). **관측**: L3 구현 착지(cutover 완료) 이후 발생한 **자연 merge_group 배치**(run_attempt=1, 임의 선택·제외 금지) 중 **최초 15배치**.

**관측 변수(배치별)**:
- `ChainWall_i` = 잔여 잡(`admission-check`) completed_at − `build-base-artifacts` started_at (잡 API, ±1s)
- `Job2bWall_i` = 잔여 잡 wall · `Job2aWall_i` = job2a wall · `minLane_i` = min(lane0, lane1) wall
- 큐 4항: 최대 동시 잡(관측 창)·created→started 갭·러너 종류·headroom(플랜 한도 대비)
- 비용 변수(§5)

**동결 게이트(단일 공식 — 문자 그대로 적용)**:

> **GO_effect ⟺ (은폐) Job2aWall_i ≤ minLane_i가 15/15** 그리고 **(절감) median(ChainWall₁..₁₅) + 2·SE_post + 2·SE_pre ≤ median(ChainWall_census₁..₁₅)**
> 여기서 `SE(median) = 1.253·σ̂/√n`(σ̂ = 표본 SD, n−1), `SE_post`는 신규 15배치·`SE_pre`는 census 15배치(`data/ci_provider/census_20261103T025821Z/` — 동결된 참조 데이터, 재계산만 허용) 각각의 ChainWall에 적용.

- **명시 판정 규칙**: paired가 불가능한 세대 간 비교이므로 양측 SE를 모두 공제하는 보수 형식을 쓴다(사전 고정 — 사후 단순화 금지).
- 진단 참조치: 절감 25s·job2a wall 87s·잔여 85s — **게이트가 아니라 참조**(사전 관측 공개: 이 값들은 게이트 동결에 선행해 산출됐음 — L3 감사 §1 규율 계승).
- **실패 시**: GO_effect 불성립 → 구현 유지 여부는 별도 판정(되돌림은 Epoch Cutover 절차의 새 세대로만 — in-place 금지). 게이트 FAIL 자체를 숨기지 않고 기록한다.
- **#1166 불간섭**: 본 게이트는 진단·구현 판정 계층이며 #1166 공식 SLO 모집단·판정창을 선점하지 않는다.

## §5. 비용 측정 계약 (공식 문서 확정 — SB-3, 2026-11-03)

병렬화는 벽시계 절감과 별개로 **runner 사용량을 증가**시킨다(공통 11스텝 재지불·3번째 toolchain restore). 동일 관측 창(§4의 15배치 + 사전 대조 census 15배치)에서:

| 항목 | 방법(공식) |
|---|---|
| run 단위 원시 사용량 | `GET /repos/Archright/Axiom/actions/runs/<run_id>/timing` — `billable.<OS>.total_ms`·`job_runs[].duration_ms`·`run_duration_ms`(재시도 포함·멀티플라이어 미적용) |
| 잡 단위 | jobs API `started_at→completed_at` 합산(잡 wall — 대기 포함 주석) |
| **과금 환산** | **잡당 정수 분 올림 × SKU 요금(Linux x64 $0.006/min)** — 공식 rounding 규칙: "GitHub rounds the minutes and partial minutes each job uses up to the nearest whole minute". **잡 분할은 잡당 최소 +1 청구 분을 확정적으로 추가** |
| 동시성 | `GET .../actions/runs?status=queued|in_progress` `total_count` 스냅샷(런 단위 — 잡 수 API는 미존재)·관측 창 최대 동시 잡 |
| artifact 전송 | 신규 채널 홉의 실측(소형 부류 기대 1s/홉 — `l3_followup §2` 경계: 대형 payload 시 +2s 수당 무효) |

- 재사용 워크플로 과금은 caller 귀속(공식) — admission-gate 런의 timing이 callee 잡을 포함한다.
- org 과금 API(`/organizations/{org}/settings/billing/usage`, enhanced billing)는 부속 관측(접근 불가 시 timing 원시값으로 종결 — 접근성 기록).
- **판정 지위**: 비용은 절감과 **별도 보고**(하나로 합산 금지 — 사용자 지시). GO_effect(§4)와 독립적으로 기록되고, 최종 운영 판정(§4 실패 시 포함)의 입력이 된다.

## §6. ADR-0032 (e) 명시 판정

ADR-0032 (e): "5-leg DAG·집계 불변, leg 생략·job skip 금지… MG의 모든 스텝·아티팩트 이름·attempt suffix는 바이트 수준 불변."

**판정: 준수 설계로 수행한다(ADR 개정 불필요)**:
- **5-leg 유지**: caller의 5 leg(attest·mint-prepare·mint-publish·verdict·gateway)·집계 불변 — 본 변경은 callee 내부 잡 배치만 조정.
- **job skip 금지 준수**: 신규 job2a는 미인식 이벤트에서 기존 스텝과 동일하게 exit 1 fail-closed(venue 분기 로직 상속). §2.4의 `!cancelled()` 생존 장치는 job skip이 아니라 잔여 잡의 명시 판정 수행이다.
- **스텝·아티팩트 이름 바이트 불변**: 이동 4스텝의 이름·기존 artifact 이름·attempt suffix 불변. **유일한 신설 표면**: job2a 잡 자체(이름 `admission-independents`)*·§2.2의 신규 산출 채널(outputs 6종 + artifact 1종 — `<candidate head>-<run_attempt>` 접미 계약 준수). 이 신설이 (e)의 "MG 스텝·아티팩트 이름 불변" 조항과 충돌하지 않는 근거: 조항이 보호하는 대상은 **MG 검증 산출의 소비 계약**(mint·verdict가 소비하는 기존 이름)이며, 신규 채널은 잔여 잡 내부 소비 전용이다. 이 해석이 승인 게이트(§8)에서 인간 아키텍트의 검토 항목 1로 명시 열거된다 — 해석 기각 시 ADR-0032 Amendment 경로로 전환(그 경우 본 사전등록 §2.2·§6은 개정 문서로 대체).

\* 잡 이름은 구현 슬랩에서 확정하되 기존 callee 잡 명명 관례(kebab-case·venue 무관)를 따른다 — 최종 이름은 Phase C PR에 기록.

## §10. Track 1 병행 시험 — 본 PR 차량 (GitHub native auto-merge)

**목적**: PR green→큐 진입 갭(수동 med 60.5s, F-3)을 auto-merge로 제거 가능함을 실운영에서 관측. **본 PR이 시험 차량**(docs-only·trustSurface 비적용·정상 arm 경로).

**동결 관측 계약(3시점 분리 — 공식 문서 + 실증 기반)**:
- `RequiredChecksGreenAt` = PR head check-runs(`per_page=100`) 중 **required 5 context**(admission-check·bsec-integrity·debt-registry-gate·generation-acceptance·axiom-operational-slice) `completed_at`의 최댍값. 단, check 실패 시 상태 전이는 공식 미문서화 — green 미달 시 관측 종료·기록.
- `EnqueuedAt` = GraphQL `AddedToMergeQueueEvent.createdAt`(타임라인 — 병합 후 사후 관측 가능; PR #1246 실증 2026-11-03). live 시 `pullRequest.mergeQueueEntry.enqueuedAt`·`headCommit.oid` 병행 기록(엔트리 소멸 전).
- `RunCreatedAt` = merge_group 런 `created_at`.
- **지표**: QueueEntryDelay = EnqueuedAt − RequiredChecksGreenAt · DispatchDelay = RunCreatedAt − EnqueuedAt(#1246 수동 실측 19s 참조).
- **arm**: `gh pr merge <N> --auto --merge --match-head-commit <head>`(gh CLI 사용자 자격 — GITHUB_TOKEN은 큐 진입 불가, 공식 문서화·Q14). arm 증거 `gh pr view <N> --json autoMergeRequest`.
- **판정 지위**: 표본 1건 — 기록이 목적(일반화 금지). auto-merge 트리거 지연 SLA는 공식 미문서화(NOT DOCUMENTED). **이 갭은 #1166 공식 SLO(merge_group admission wall) 이전 구간** — SLO 개선으로 주장하지 않는다(merge_group 이벤트는 큐 진입 시에만 발생 — 공식).
- **실패 안전**: 필수 check 실패 시 PR은 큐에서 제거·타임라인 사유 기록·미보고 check는 타임아웃 후 실패 간주(플랫폼 fail-closed, 공식).
- **F-4 기록**: 관측값(3시점·갭 2종·명령·auto-merge 상태)은 Phase C 증거 번들 또는 후속 docs PR에 착지(본 PR에는 계약만 동결).

**3증거 readback(리뷰 B 반영 — 본 PR 착지 검증에 즉시 적용)**:
1. **그룹 식별**: merge_group 런의 `head_sha`(= 그룹 SHA — 공식 "SHA of the merge group")·PR 타임라인 RemovedFromMergeQueueEvent/MergedEvent. 문서화된 2홉(`pullRequest.mergeQueueEntry.headCommit` → `runs?event=merge_group&head_sha=`)은 엔트리 존속 중 병행 기록.
2. **런 검증**: 해당 그룹 SHA로 8/8 success 관측 + **조인 사실 기록**: `merge_commit_sha == 그룹 SHA` — 공식 미보증(NOT DOCUMENTED)·본 저장소 경험적 불변(4회 8/8 readback: #1242·#1245·#1246·#1247 계열). **불일치 관측 시 쿼리 버그가 아니라 플랫폼 행동 변화로 에스컬레이션**한다.
3. **main 반영**: `git fetch origin main` tip == merge 커밋·부모(PR head 포함)·`git ls-tree` vs `git hash-object`(신규 문서 blob) + 양 org ruleset 핀 `7eaa9624…` 불변·active(docs-only 착지).
