# Feature Manifest Atomicity

**Created**: 2026-06-20
**Status**: Implemented
**Policy**: AGENTS.md §0.5b Quirk Documentation Mandate

## Problem Statement

`feature_manifest.json` is generated by scanning the filesystem. If the generator is interrupted mid-write, or if concurrent processes read the file while it's being written, the manifest may be:
1. **Corrupted**: Partial JSON (truncated at filesystem boundary)
2. **Stale**: Read during write (TOCTOU race)
3. **Inconsistent**: Content hash doesn't match file contents

## Solution: Atomic Write

The manifest generator uses the **temp+fsync+rename** pattern for atomic writes:

```
1. Write complete JSON to data/feature_manifest.json.tmp
2. fsync the temp file (ensure data reaches disk)
3. Rename temp → data/feature_manifest.json (atomic on POSIX)
```

### Implementation

In `tools/feature_manifest_generator.nim`:

```nim
proc writeManifestAtomic*(manifest: JsonNode; path: string) =
  let tmpPath = path & ".tmp"
  let content = manifest.pretty()
  
  # Write to temp file
  writeFile(tmpPath, content)
  
  # fsync to ensure data reaches disk
  let fd = open(tmpPath, fmRead)
  try:
    fd.flushFile()  # This triggers fsync on POSIX
  finally:
    close(fd)
  
  # Atomic rename (POSIX guarantee)
  moveFile(tmpPath, path)
```

### source_hash Field

The manifest includes a `source_hash` field computed from all `.feature` files:

```json
{
  "version": "2.0",
  "generated_at": "2026-06-20T...",
  "feature_count": 647,
  "source_hash": "sha256:a1b2c3d4...",
  "features": [...]
}
```

The hash is computed as:
1. Collect all `.feature` file paths
2. **Sort alphabetically** (deterministic order)
3. For each file: `SHA-256(path + ":" + SHA-256(content))`
4. Chain all hashes: `SHA-256(hash1 + "\n" + hash2 + "\n" + ...)`

### Staleness Detection

config.nims can detect manifest staleness by comparing:
1. `source_hash` in manifest vs recomputed hash
2. `generated_at` timestamp vs filesystem modification times

```nim
# In config.nims (future):
if fileExists("data/feature_manifest.json"):
  let manifest = parseJson(readFile("data/feature_manifest.json"))
  let storedHash = manifest["source_hash"].getStr()
  let computedHash = computeSourceHash("tests/gateway/features")
  if storedHash != computedHash:
    echo "WARNING: feature_manifest.json is stale. Regenerating..."
    # Trigger regeneration
```

## Concurrency Considerations

### Current State
- Single-process generation (no concurrent writes)
- Atomic write prevents corruption
- No lock mechanism (acceptable for build-time only)

### Future: Multi-Process Build
If parallel builds are introduced:
1. Use file locking (`flock` on Linux, `LockFile` on Windows)
2. Or use a lock file pattern: `data/feature_manifest.lock`
3. Reader processes should check lock before reading

### Known Limitations
- **Linux-only**: `fsync` behavior differs on Windows (use `FlushFileBuffers`)
- **NFS/network filesystems**: Rename may not be atomic across network boundaries
- **Power loss**: Data may still be in OS cache (fsync mitigates but doesn't eliminate)
