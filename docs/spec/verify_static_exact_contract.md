## Purpose

This document defines the canonical contract for reproducing the `verify-static` CI job
locally with **bit-identical semantics**. Two executors — the CI runner and the local
developer runner — must reach the same verdict for every gate if the input snapshot,
policy, and toolchain are identical.

The contract does not introduce new gates or new tooling. It documents the existing
ordered pipeline so that any deviation (local vs CI, or across CI runs) is detectable,
attributable, and actionable.

---

## The LocalExact Invariant

```
LocalExact(STATE) == CI(STATE)
```

- **Same gate set** — all 18 steps are executed, in the declared order, without omission
- **Same order** — step N runs only after step N−1 has reported
- **Same argv / env / policy** — source snapshot, generated-artifact manifest, debt baseline,
  and toolchain identity are pinned (see §Input Closure)
- **Same per-gate verdict** — a failure records the same gate id, rule, and fingerprint
  locally as it would in CI; accepting that "Local FAIL == CI FAIL semantically"

An intentional violation (e.g., a known broken invariant that deliberately fails one gate)
must fail locally **and** in CI with the **same gate id + rule + fingerprint**. It is not
sufficient to match only the exit code.

## Input / Policy / Environment Closure

For `LocalExact == CI` to hold, every variable the gates inspect must be pinned.

### Source Snapshot

The working tree at invocation time. The CI job first performs a destructive reset
(`git reset --hard HEAD && git clean -ffdx …`) to establish a clean snapshot. Locally,
the developer is responsible for a clean tree (enforced by the purity check, step 18).
The toolchain pin verification is non-destructive (see §Non-Destructive Reuse).

### Generated Artifacts

These files are produced by code-generators during the gate run and are **not**
pre-committed in CI. Locally they must be regenerated by the drift-guard steps
(steps 15–16):

| Path | Generator |
|------|-----------|
| `src/gate/manifest.d/*.json` | `tools/sync_topology.nim` |
| `src/generated/manifest_registry.nim` | `tools/sync_topology.nim` |
| `src/generated/gate_registry.nim` | `tools/sync_topology.nim` |
| `src/generated/helper_registry.nim` | `tools/sync_topology.nim` |
| `config/gates.manifest.toml` | `tools/sync_topology.nim` |
| (decision graph artifacts) | `tools/sync_decisions.nim` |

### Debt Baseline

`data/nimtry_baseline.json` — the tracked snapshot used by the debt gate (step 5).

### Whitelist

Any exemption list consumed by individual gates (e.g., theater whitelist, debt waiver).
These are sourced from `config/` and must match between local and CI environments.

### Toolchain Identity

| Tool | Pin | Verified by |
|------|-----|-------------|
| Nim | 2.2.10 | `nim --version` |
| Z3 | 4.13.3 | `z3 --version` |
| Lean | 4.33.0 | `lean --version` |

Pins are installed by `.github/actions/setup-axiom-toolchain` and verified in the
CI determinism-guard step. Locally, the `make check-toolchain-pin` target
(substituted for the destructive git-clean) verifies these pins without modifying the tree.

### Environment Variables

| Variable | Value | Effect |
|----------|-------|--------|
| `AXIOM_CI` | `1` | Enables CI-only guards and suppresses interactive prompts |
| `AXIOM_CI_PRESERVE_CACHE` | `1` | Prevents cache invalidation between gate runs |

Both must be set for local runs that seek CI-equivalent behavior.

### Invocation Policy

- Gates run **serially** in the declared order; parallelism within a gate is internal
- A gate that errors (as opposed to failing) halts the pipeline — no subsequent steps run
- `if: always()` on the decision-binding step (step 14) means it runs even if earlier
  steps failed; all other steps run sequentially without `if: always()`

## Canonical 18-Step Ordered Table

Each CI step maps 1:1 to a local Makefile target. The exact command is the Makefile's
recipe; the table records the semantic contract for each step.

| # | CI Step Name | Local Makefile Target | Semantic Contract |
|---|--------------|----------------------|-------------------|
| 1 | Mutation harness | `make check-mutation-harness` | Runs the mutation-testing harness to validate gate fault-sensitivity |
| 2 | Environment check | `make env-check` | Verifies all required runtime dependencies are present and reachable |
| 3 | Check imports | `make check-imports` | AST-scans `src/` for import anomalies (unused, duplicated, cyclical) |
| 4 | Check MCP | `make check-mcp` | Validates MCP server configuration and wire-protocol contract |
| 5 | Check debt | `make check-debt` | Compares `data/nimtry_baseline.json` against current debt registry |
| 6 | Check manifest consistency | `make check-manifest-consistency` | Cross-validates gate manifest entries against their implementations |
| 7 | Check certificate manifest drift | `make check-cert-manifest-drift` | Detects uncommitted changes to `src/gate/manifest.d/*.json` |
| 8 | Certificate integrity (full) | `make check-cert-integrity` | Full proof-certificate integrity validation across the vault |
| 9 | Check architecture | `make check-arch` | Architecture invariant scanner (layer boundary, naming, cyclic deps) |
| 10 | Check Nim theater | `make check-nim-theater` | Scans for theater markers (always-pass, dead gates, vacuous proofs) |
| 11 | Check Lean vacuity | `make check-lean-vacuity` | Validates Lean proof files are non-vacuous (not trivially true) |
| 12 | Check vacuity simple | `make check-vacuity-simple` | Lightweight vacuity check on trivial test / proof artifacts |
| 13 | Doc path validator | `make doc-path-validator` | Validates all `docs/` references in source resolve correctly |
| 14 | Decision binding audit | `make check-decision-binding` | Compiles and runs `tools/hermetic_build.nim` → `bin/hermetic_build --check-decision-bindings --escalation-threshold 30` |
| 15 | Verify topology drift | `make check-topology-drift` | Rebuilds `bin/sync_topology` from `tools/sync_topology.nim`, runs it, then `git diff --exit-code` on generated files (`src/gate/manifest.d/*.json`, `src/generated/manifest_registry.nim`, `src/generated/gate_registry.nim`, `src/generated/helper_registry.nim`, `config/gates.manifest.toml`) |
| 16 | Verify decision graph drift | `make check-decision-graph-drift` | Rebuilds `bin/sync_decisions` from `tools/sync_decisions.nim --ci-drift-check` and runs it |
| 17 | SLOC governance verify | `make sloc-verify` | Canonical SLOC governance verifier (sibling gate; enforcement authority) |
| 18 | Git tree purity (read-only) | `make check-git-purity` | `git status --porcelain` must produce no output; checked **last** |

### Steps 14–16 as Code-Generated-Drift Guards

Steps 14, 15, and 16 are distinguished from passive gate checks in that they
**produce or validate generated artifacts**:

- **Step 14** (`check-decision-binding`): Compiles `hermetic_build.nim` and audits
  decision-binding metadata. The binary is a new artifact, but it is placed in `bin/`
  (already gitignored) and the check itself is read-only against source.
- **Step 15** (`check-topology-drift`): Compiles `sync_topology.nim`, runs it to
  regenerate `src/gate/manifest.d/*.json` and the `src/generated/*.nim` + `config/*.toml`
  files, then verifies those files are identical to their committed versions. Any diff
  indicates the topology spec has drifted from the committed generated artifacts.
- **Step 16** (`check-decision-graph-drift`): Compiles `sync_decisions.nim`, runs it
  with `--ci-drift-check` to verify the decision graph is consistent with committed state.

These three steps are the mechanism by which the system detects **code-generation drift** —
a situation where a change to a specification file is not reflected in the generated
artifacts, or vice versa. They are run unconditionally in both CI and local pipelines.

## Evidence / Fingerprint Contract

When a gate fails, it records:

- **gate id**: the symbolic name of the failing gate (e.g., `check-debt`, `check-arch`)
- **rule**: the specific rule within the gate that was violated
- **fingerprint**: a stable hash of the inputs that produced the failure (source snapshot
  content, policy version, or artifact hash as appropriate)

The fingerprint is deterministic: the same input snapshot produces the same fingerprint
in both local and CI environments. This allows a failure observed in CI to be reproduced
locally with the same root cause, and vice versa.

**Acceptance**: If step N reports FAIL locally, step N must report FAIL in CI on the same
input snapshot. If step N reports PASS locally, step N must report PASS in CI on the same
input snapshot. The invariant does not require that *all* steps pass — only that their
verdicts are consistent across executors.

## Non-Destructive Reuse Principle

### Why `git clean` Is Not Reproduced Locally

The CI determinism-guard step runs:

```bash
git reset --hard HEAD
git clean -ffdx -e build/nimcache -e build/gateway-tests -e .axiom/cache -e proofs/.lake -e data/.coverage_baseline_main.json
```

This is **destructive**: it discards all uncommitted changes, including staged work,
unstaged edits, and untracked files within the exclusion list. Running this on a
developer tree would erase active work without confirmation.

**The local exact path does not run this command.** The developer is responsible for
committing or stashing work before running the local pipeline. The pipeline itself
must not modify tracked files (enforced by step 18).

### What `check-toolchain-pin` Substitutes

Instead of the destructive reset, the local pipeline uses `make check-toolchain-pin`
to verify the three tool version pins without touching the working tree:

```bash
nim --version | grep 2.2.10
z3 --version | grep 4.13.3
lean --version | grep 4.33.0
```

If the installed toolchain does not match, the target fails with a clear diagnostic.
The developer must install the correct toolchain versions before running the pipeline.

### Why Purity Must Be Last

Step 18 (`make check-git-purity`) runs **after** all other steps. This ordering is
intentional:

1. Steps 1–17 may legitimately produce new untracked files (e.g., compiled binaries
   in `bin/`, nimcache artifacts in `build/nimcache/`, proof lake in `proofs/.lake`).
   These are gitignored and do not appear in `git status --porcelain`.
2. By running purity last, the pipeline confirms that **no step modified tracked files**.
   Any modification to a tracked file by an earlier step is an error.
3. Placing purity first would create a false positive: untracked artifacts from
   step 1 (e.g., the first `nim c` compilation) would appear dirty even if the
   verification process was entirely clean.

The CI pipeline uses a destructive reset **before** all gates precisely to establish
a known clean baseline. Locally, the developer provides the clean baseline by
committing or stashing work before invocation.

## How to Run

### Standard Local Execution

```bash
AXIOM_CI=1 AXIOM_CI_PRESERVE_CACHE=1 make local-verify-static-exact
```

This aggregate target (added in parallel to the Makefile per B2) runs all 18 steps
in order, with `check-toolchain-pin` substituted for the destructive git-clean.
All `AXIOM_CI*` env vars must be set to suppress interactive prompts and enable
CI-only guards.

### Recording Evidence for an Intentional-Violation Test

To deliberately trigger a known failure and capture its fingerprint for comparison:

```bash
# 1. Isolate the failing state (e.g., add an I/O call to a pure func)
$EDITOR src/core/domain_utils.nim   # introduce the deliberate violation

# 2. Run the specific gate (step N) in isolation
make check-debt    # or whichever gate is being tested

# 3. Capture the full output including gate id, rule, and fingerprint
make check-debt 2>&1 | tee /tmp/violation-evidence.txt

# 4. Verify the same failure reproduces in CI (push and inspect the run)
git add -A && git commit -m "test: intentional violation evidence"
git push origin local-exact-verify-static

# 5. Compare fingerprints: local evidence vs CI log
#    Gate id + rule + fingerprint must match exactly
```

## Boundaries / Non-Goals

This document defines the **contract** for the `verify-static` pipeline. It explicitly
does **not**:

- Modify `Makefile` gate aggregate definitions — the Makefile targets are the authoritative source (CI workflow definitions retired with the CI=0 cutover, 2026-09-20)
- Modify `AGENTS.md` or any gate implementation
- Introduce new gate names — all 18 steps reuse the exact Makefile targets listed above
- Modify the Makefile — the `local-verify-static-exact` aggregate target is being added
  in parallel (tracked as work item B2)
- Enable new memoization, cache-reuse, or daemon modes that would alter gate semantics
- Substitute a different test runner for any gate implementation

Any change that alters the gate set, gate order, or gate verdict for a given input
snapshot is a **contract violation** and must be documented as a revision to this
document before being merged.
