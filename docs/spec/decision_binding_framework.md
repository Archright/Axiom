# Decision Binding Framework

**Status**: Proposed  
**Created**: 2026-07-31  
**Related**: AGENTS.md §0.10, `data/debt_registry.json`, `docs/adr/`

---

## Purpose: Pull-based → Push-based Paradigm Shift

### Problem

Stateless agent sessions cannot discover "why" decisions were made. When an agent encounters a symbol like `type ProofReceipt = object { ... }`, it can read *what* the type looks like but not *why* it was designed that way. The current system requires agents to "pull" context from scattered sources (commit messages, PR descriptions, ADR documents) — a process that is lossy, time-consuming, and unreliable.

### Solution

The **Decision Binding Framework** pushes decision narratives directly into the codebase through compile-time annotations. Every public type and proc carries `{.axiomDecision.}` pragma that encodes:

- **What** the symbol does (functional description)
- **Why** it exists (design rationale / DEBT reference)
- **Where** the full narrative lives (`docs/adr/ADR-XXXX.md`)
- **When** it was introduced (commit hash or version tag)

This transforms every symbol from a passive data structure into an active knowledge carrier. Agents read the pragma at the point of use — no pull-based discovery required.

## Pillar 1: AST Annotation (`{.axiomDecision.}` pragma)

### Specification

Every public type and proc declaration MUST carry the `{.axiomDecision.}` pragma with structured metadata:

```nim
type
  ProofReceipt* = object {.axiomDecision(
    id: "DECISION-0001",
    reason: "Atomic receipt serialization for cross-process integrity",
    adr: "docs/adr/0001-fail-closed-result-type.md",
    introduced: "v27"
  ).}
    status*: ReceiptStatus
    gateResults*: seq[GateResult]
    signature*: string

proc verifyReceipt*(r: ProofReceipt): bool {.axiomDecision(
  id: "DECISION-0002",
  reason: "Fail-closed verification — any corruption returns false",
  adr: "docs/adr/0001-fail-closed-result-type.md",
  introduced: "v27"
).} =
  # implementation
```

### Pragma Format

```
{.axiomDecision(
  id: "DECISION-NNNN",       # Unique identifier (required)
  reason: "...",             # One-line design rationale (required)
  adr: "path/to/adr.md",     # Full narrative location (optional if trivial)
  introduced: "vXX"          # Version or commit hash (optional)
).}
```

### Enforcement Rules

| Rule | Description |
|------|-------------|
| R1 | All `public*` types/procs in `src/core/` MUST have `{.axiomDecision.}` |
| R2 | Gate runner procs in `src/gate/runners/` MUST have `{.axiomDecision.}` |
| R3 | Internal/private symbols are exempt (no `*` export) |
| R4 | `{.axiomDecision.}` pragma is a compile-time directive; zero runtime cost |
| R5 | Missing pragma on public symbol = lint error (see Pillar 4) |

### Relationship to Existing Pragmas

`{.axiomDecision.}` is orthogonal to existing pragmas:

```nim
proc computeHash*(data: string): string {.
  axiomDecision(id: "DECISION-0010", reason: "SHA256 for immutability guarantee"),
  axiomEffect(IoEffect),
  raises: [],
  noSideEffect.
} =
  # implementation
```

Multiple pragmas stack without conflict. The compiler processes them in order: effect system → decision binding → purity.

## Pillar 2: Decision Knowledge Graph (`decisions_graph.json`)

### Overview

`decisions_graph.json` is the machine-readable index of all `{.axiomDecision.}` annotations in the codebase. It serves as:

1. **Cross-reference map**: Link symbols to their ADR narratives
2. **Dependency tracker**: Identify which decisions depend on others
3. **Coverage dashboard**: Show what percentage of public API is annotated

### Location

Generated artifact at repository root: `decisions_graph.json`

### Generation

Generated by the Decision Binding Linter (Pillar 4) during build. Not committed manually — always regenerated from source.

### Schema

See §Schema below for full JSON schema definition.

## Pillar 4: CI/CD Deterministic Linter

### Role

The Decision Binding Linter enforces Pillar 1 at build time. It runs as part of the hermetic build pipeline (triggered by `config.nims` `hermeticPreBuild` block).

### Linter Behavior

1. **Scan phase**: Walk all `src/**/*.nim` files, parse AST for `public*` symbols
2. **Check phase**: Verify each public symbol has `{.axiomDecision.}` pragma
3. **Report phase**: Emit warnings for missing pragmas, errors for blocked symbols
4. **Generate phase**: Produce/update `decisions_graph.json`

### Integration with Hermetic Build

```nim
# In config.nims hermeticPreBuild block:
when defined(decisionBindingLint):
  static:
    echo "[hermeticPreBuild] Running decision binding linter..."
    let results = decisionBindingLint()
    if results.errors.len > 0:
      for err in results.errors:
        echo "ERROR: " & err
      quit(1)
    else:
      echo "Decision binding check passed: ", results.annotated, "/", results.total, " public symbols"
```

### Fail-open Policy

Unlike critical gates (theater prohibition, import encapsulation), the decision binding linter operates in **warning mode** during grandfathering period. It transitions to **error mode** once all public symbols are annotated.

Transition criteria:

- The waiver set that the runtime actually consumes has zero active waivers — this bullet states the transition **end-state**, not the current fact: as of 2026-10-17, **259** `grandfather` entries are active (all `expires = 2026-12-31`). Current consumption: the checker is **JSON-only** — it loads `config/decision_binding.waiver.json` alone (`tools/decision_binding_checker.nim:120`, 줄번호는 2026-11-10 stale 불변조건 추가 후 재인용) and a load failure is fail-closed `quit(1)` (`:406-410`); there is no TOML fallback (the line once cited as one, `:162`, is now the `Loaded N active waiver(s)` echo). The gate also reads JSON only (`src/gate/runners/decision_binding_gate.nim:89`). The only dual-file consumer is the hermetic build, which merges **both** files with TOML first (`tools/hermetic_build.nim:1607` TOML, `:1696` JSON; a JSON load failure there is WARNING-only, `:1714`). The evidence CAS digests the JSON as `PolicyDigestInputPaths[0]` (`src/verification/evidence_cas.nim:96-101`; the TOML is absent from the digest set)
- All `LEGACY-0000` markers resolved or migrated
- CI passes with `--decisionBindingLint` flag

## Grandfathering Strategy

### Waiver Configuration

`config/decision_binding.waiver.toml` provides temporary exemptions for existing public symbols. The deployed schema is a top-level `[[grandfather]]` array. Each entry grants an exemption to a **file** (not a symbol) for a stated reason until an expiry date.

**두 파일은 같은 데이터가 아니다 (2026-10-04 실측)**: `python3` 파싱 결과 `[[grandfather]]` 항목 수는 **TOML 23개 / JSON 259개**로 서로 다르다. 따라서 둘은 하나의 데이터의 서로 다른 표현이 아니라 **내용이 발산한 별개 파일**이다. 소비 형상(2026-10-17 관측; 줄번호는 2026-11-10 stale 불변조건 추가 이후 기준으로 재인용) — `tools/decision_binding_checker.nim:120`은 **JSON 전용**이다(`config/decision_binding.waiver.json` 단일 경로; 로드 실패 시 fail-closed `quit(1)`, `:406-410` — TOML 폴백은 존재하지 않으며, 예전에 폴백으로 인용되던 `:162`는 이제 `Loaded N active waiver(s)` 에코다); `src/gate/runners/decision_binding_gate.nim:89`도 JSON만 읽는다; 양파일을 모두 읽는 유일 소비자는 허메틱 빌드로 **TOML을 먼저 병합**한다(`tools/hermetic_build.nim:1607` TOML, `:1696` JSON — JSON 로드 실패는 WARNING만, `:1714`); 증거 CAS는 JSON을 `PolicyDigestInputPaths[0]`로 다이제스트한다(`src/verification/evidence_cas.nim:96-101` — TOML은 다이제스트 집합에 없음). 활성 항목은 2026-10-17 기준 **259건**(전부 `expires = 2026-12-31`)이다. 두 파일 중 어느 쪽이 정본인지는 **여기서 판정하지 않는다**(아키텍트 제안이 열려 있음) — 본 문서는 파싱 실측과 런타임 소비 형상이라는 사실만 기술한다.

> 유니온 259 분류표·TOML 삭제 실측 등가성(EQ-TEST, CONFIRMED)·결정 시한 제안(2026-11-30)을 포함한 정본 감사 전문은 `docs/evidence/waiver_canonical_audit_2026-10-17.md`에 있다.

**Deployed schema** — top-level section `grandfather`, fields `file`, `reason`, `expires`:

```toml
# config/decision_binding.waiver.toml
# Top-level section: [[grandfather]]
# Fields: file, reason, expires

[[grandfather]]
file = "src/core/trusted/architecture_invariants.nim"
reason = "Pre-existing core invariants predate decision-binding policy"
expires = "2026-12-31"

[[grandfather]]
file = "src/gate/static_gate_scanner.nim"
reason = "Pre-existing gate scanner predates decision-binding policy"
expires = "2026-12-31"
```

**Expiry mechanics**: both consumers (`tools/hermetic_build.nim:1761-1842` and
`tools/decision_binding_checker.nim`) compare each entry's `expires` date against
today (`TC_ISO8601`). An entry whose `expires < today` is treated as **expired**:
it is excluded from the exempt set and reported as `WAIVER EXPIRED`. Only
non-expired entries grant exemption. The JSON form mirrors this exactly —
`root["grandfather"]` is an array of `{ "file", "reason", "expires" }` objects.

**Stale-waiver 불변조건 (checker, 2026-11-10)**: `tools/decision_binding_checker.nim`는
JSON 로드 직후·위반 스캔 전에 **모든** `grandfather` 엔트리의 `file`이 저장소 트리에
존재하는지 검증한다(`findStaleWaiverFiles`, 만료 여부와 무관하게 전체 배열 대상).
대상 파일이 없는 엔트리는 **stale waiver**(죽은 면제)다 — 스캔되는 어떤 경로와도
매칭될 수 없어 면제 집합을 조용히 축소하고, 한때 덮었던 파일보다 오래 살아남는다.
checker는 이 경우 fail-closed로 로드를 거부한다: `exit 1` + 해당 엔트리 경로 전체를
나열하는 진단. 정리 경로는 waiver 파일에서 해당 엔트리 제거뿐이며 우회·면제는 없다.
`--audit-mode`로도 우회되지 않는다 — 로드 무결성 실패는 감사 모드 분기에 앞선다
(누락·불완전·malformed 로드와 동일한 fail-closed 등급). 다른 소비자
(`src/gate/runners/decision_binding_gate.nim`·`tools/hermetic_build.nim`·
`src/verification/evidence_cas.nim`)는 대상 파일 존재를 검증하지 않으므로(관측
2026-11-10), checker의 로드 시점이 이 불변조건의 유일 시행 지점이다.

**Field set**:

| Field | Type | Description |
|-------|------|-------------|
| `file` | string | Path (relative to repo root) of the exempted source file |
| `reason` | string | Explanation for the exemption |
| `expires` | string | ISO 8601 date (`YYYY-MM-DD`) after which the waiver is invalid |

> Note: the original framework proposal used a `[[waivers]]` array keyed by
> `symbol` with a `legacyId` field. That schema is **not** deployed. The deployed
> schema is file-scoped via `[[grandfather]]` with `file`/`reason`/`expires`.
> See `docs/agents/decision_binding_schema_revision_proposal.md`.

### LEGACY-0000 Pattern

Symbols covered by waivers use the `LEGACY-0000` exemption marker in comments:

```nim
# LEGACY-0000: Waived — see config/decision_binding.waiver.toml
# Will receive { .axiomDecision } when DEBT#0042 is resolved
type PipelineContext* = object
  # ... fields ...
```

The linter recognizes `LEGACY-0000` markers and skips those symbols during checking. This prevents immediate CI breakage while providing a clear migration path.

| Phase | Duration | Action |
|-------|----------|--------|

## Performance Safety: Native Binaries vs NimScript VM

### Why Not NimScript?

NimScript (`.nim` executed via `nim script`) runs inside the Nim interpreter VM. While convenient for build scripts, it introduces:

1. **Non-deterministic execution order**: NimScript's dynamic dispatch can reorder operations between runs
2. **VM overhead**: Parsing + interpreting adds ~200ms per pass — unacceptable for CI feedback loops
3. **No compile-time guarantees**: NimScript lacks `{.raises: [].}` enforcement, making error handling unpredictable
4. **Version lock-in**: NimScript behavior varies across Nim versions, breaking hermetic builds

### Why Native Binary?

The Decision Binding Linter is compiled as a native binary (`bin/decision_binding_checker`) with:

- **Deterministic output**: Same input → identical JSON graph every time
- **Zero VM overhead**: Compiled AST traversal is ~10x faster than NimScript interpretation
- **Compile-time safety**: Uses same `{.raises: [].}` discipline as core engine
- **Hermetic compatibility**: Self-contained binary, no external dependencies beyond Nim stdlib

### Bootstrap Process

```
1. config.nims detects --decisionBindingLint flag
2. hermeticPreBuild compiles bin/decision_binding_checker from tools/decision_binding_checker.nim
3. Linter runs as standalone process (not NimScript)
4. Output written to decisions_graph.json
5. Main compilation proceeds with graph as validation artifact
```

This mirrors the AOT Precompile Pipeline (§3 ENVIRONMENT) used for gate binaries.

## Usage Guide: Adding `{.axiomDecision.}` to a New Symbol

### Step-by-step

1. **Write the symbol** as normal (type or proc):

   ```nim
   type MyNewType* = object
     field1: int
     field2: string
   ```

2. **Identify the decision rationale**: Why does this exist? What problem does it solve? Check `docs/adr/` for related ADRs.

3. **Assign a DECISION ID**: Pick next available number (e.g., `DECISION-0050`). Check `decisions_graph.json` for gaps.

4. **Add the pragma**:

   ```nim
   type MyNewType* = object {.axiomDecision(
     id: "DECISION-0050",
     reason: "Normalized error classification for deterministic retry logic",
     adr: "docs/adr/ADR-XXXX.md",
     introduced: "v32"
   ).}
     field1: int
     field2: string
   ```

5. **Create or update the ADR** in `docs/adr/` following the standard template.

6. **Run the linter** to verify:

   ```bash
   nim c -d:decisionBindingLint bin/axiom.nim
   ```

7. **Commit** both the code change and the ADR together.

### Common Patterns

**Simple type (trivial rationale)**:

```nim
type LogLevel* = enum Debug, Info, Warning, Error {.axiomDecision(
  id: "DECISION-0051",
  reason: "Four-level logging matches CLI output tiers"
).}
```

**Proc with multiple pragmas**:

```nim
proc validate*(input: RawInput): Validated {.
  axiomDecision(id: "DECISION-0052", reason: "Separate raw/validated types prevent unvalidated data flow"),
  raises: [ParseError],
  noSideEffect.
} =
  # implementation
```

**Waived symbol (temporarily)**:

```nim
# LEGACY-0000: Waived — see config/decision_binding.waiver.toml
# Target: annotate by Phase 5c deadline
type LegacyType* = object
  oldField: string
```

## Progressive Escalation (D-30 Soft Gate → D-Day Hard Fail)

### Concept

Waiver expiration is not an instantaneous hard fail. The decision binding gate uses a **three-state progressive escalation** model that gives teams time to resolve violations before blocking CI.

### Three States

| State | Trigger | Behavior |
|-------|---------|----------|
| **PASS** | Waiver active and not expired | No action. Symbol is exempt from pragma requirement. |
| **WARN** | Waiver expired, but within escalation threshold (default: 30 days past expiry) | Gate emits warnings only. Build succeeds. Violations logged with days-since-expiry countdown. |
| **FAIL** | Waiver expired + threshold exceeded | Gate fails the build. All missing pragmas reported as errors. No bypass without new waiver. |

### Escalation Threshold

Configured via `--escalation-threshold` parameter (integer, days). Default: `30`.

```bash
# Use custom threshold (e.g., 60 days)
decision_binding_checker --staged-only --escalation-threshold 60

# Default behavior (30 days)
decision_binding_checker --staged-only
```

When set to `0`, expired waivers immediately cause FAIL (no soft gate period).

### Example Log Output

**PASS state** — waiver active:

```
[decision-binding] Loaded 3 active waiver(s) from decision_binding.waiver.json
[decision-binding] Found 0 violation(s)
[decision-binding] PASS: All decision-point functions carry pragma
```

**WARN state** — waiver expired, 15 days past expiry (within 30-day threshold):

```
[decision-binding] WAIVER EXPIRED: src/core/vault/vault_factory.nim (expired 2026-07-16, 15 days ago)
[decision-binding] Loaded 2 active waiver(s) from decision_binding.waiver.json
[decision-binding] Found 1 violation(s)
[decision-binding] WARN: src/core/vault/vault_factory.nim — 1 function(s) missing pragma (waiver expired 15 days ago, threshold: 30 days)
[decision-binding] Audit mode — no failures reported
```

**FAIL state** — waiver expired + threshold exceeded:

```
[decision-binding] WAIVER EXPIRED: src/core/vault/vault_factory.nim (expired 2026-07-16, 45 days ago)
[decision-binding] Loaded 2 active waiver(s) from decision_binding.waiver.json
[decision-binding] Found 1 violation(s)
[decision-binding] FAIL: src/core/vault/vault_factory.nim — 1 function(s) missing pragma (waiver expired 45 days ago, threshold exceeded)
[decision-binding] FAIL: 1 function(s) missing {.axiomDecision.} pragma
```

### Integration with Grandfathering Policy

The escalation states extend the existing grandfathering timeline (§Grandfathering Strategy above):

| Phase | Waiver Status | Escalation State |
|-------|---------------|-----------------|
| Phase 5a–5d | Active | PASS |
| Post-deadline ≤ 30 days | Expired, within threshold | WARN |
| Post-deadline > 30 days | Expired, threshold exceeded | FAIL |
| Phase 5e | All resolved | PASS (error mode enabled) |
