# Pending Feature Guard — Compile-time Enforcement

## Purpose
Transforms `@pending` features from "TODO later" to "build-breaking bug".

## Enforcement Flow
1. `nim c src/gate/git.nim` → config.nims runs
2. config.nims `manifestBootstrap` block ensures `data/feature_manifest.json` is fresh
3. config.nims pending guard block checks manifest for `@pending` tags
4. If pending count > 0 → `quit(1)` with clear error message
5. Developer runs `nim c -r tools/feature_scaffold_generator.nim`
6. Generator creates features WITHOUT `@pending` tag
7. Build succeeds

## Bootstrap
- Manifest missing → auto-generated by config.nims `manifestBootstrap` block
- `.feature` files newer than manifest → auto-regenerated
- `nim genmanifest` → manual regeneration

## Integration Points

### config.nims (NimScript — runtime check)
- Direct `gorge` + `quit(1)` because NimScript cannot `import` regular Nim modules
- Runs on every `nim c` invocation
- Respects `-d:AxiomParsingImports` compile-time recursion guard (skips during parse tool compilation)

### `src/core/feature_manifest_guard.nim` (compile-time check)
- For use by OTHER modules that want to enforce the check at their compile time
- Uses `when` + `gorge` + `{.error.}` for compile-time enforcement
- Only active in non-release builds (`when not defined(release)`)
- Bootstrap-safe: only checks when manifest file exists

## Usage

### As config.nims guard (automatic)
No action needed — runs on every build automatically.

### As module-level compile-time guard
```nim
import core/feature_manifest_guard  # compile-time guard: fails if data/feature_manifest.json is missing
```

## Error Message
```
ERROR: @pending features detected (450).
All features must be resolved before build.
Run: nim c -r tools/feature_scaffold_generator.nim
```
